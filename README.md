# UI Automation Project: Яндекс.Самокат

Проект содержит **end-to-end (E2E) автотесты** для веб-приложения [Mesto](https://qa-mesto.praktikum-services.ru) — сервиса для обмена фотографиями (аналог Instagram).  
Тесты покрывают следующий функционал:

- Авторизация пользователя (логин/пароль)
- Редактирование профиля (имя, описание, аватар)
- Работа с карточками (добавление, удаление, лайки)
- Валидация форм и обработка ошибок

Тесты запускаются на двух окружениях: `dev` (тестовый стенд) и `stage` (предпродакшн).

## 🛠 Технологии

| Инструмент                  | Назначение |
|-----------------------------|------------|
| **Python 3.10**             | Язык написания тестов |
| **Playwright**              | Управление браузером (автоматизация действий) |
| **Pytest**                  | Фреймворк для запуска тестов и управления фикстурами |
| **Allure**                  | Формирование детальных отчётов |
| **pydantic-settings**       | Загрузка конфигурации из `.env` |
| **Docker + Docker Compose** | Запуск тестов в изолированной среде |
| **GitHub Actions**          | CI/CD для автоматического запуска тестов и публикации отчётов |

**Структура проекта**

Вот как выглядит структура нашего E2E фреймворка:

```
qa-mesto/
│
├── conftest.py
├── requirements.txt
├── pytest.ini
├── .env.example
│
├── config/
│   ├── application.py
│   └── environments.py
│
├── pages/
│   ├── base_page.py
│   ├── home_page.py
│   └── login_page.py
│
└── tests/
    ├── test_login.py
    └── test_profile_edit.py
```

- **conftest.py** — настройки и фикстуры для pytest: управление браузером, окружениями, пользователями.
- **requirements.txt** — список библиотек (Playwright, pytest, Allure и т.д.).
- **pytest.ini** — централизованные настройки для запуска тестов.
- **config/application.py** — точка входа для всех Page Object'ов.
- **config/environments.py** — настройки окружений (dev, stage) и тестовые пользователи.
- **pages/** — Page Object Model: каждая страница приложения — отдельный класс.
- **tests/** — тестовые сценарии с Allure-аннотациями.

## 💻 Локальный запуск 

### Предварительные требования
- Python 3.12 или выше
- Установленный браузер (Chrome/Firefox/Edge)

### Установка и запуск

1. **Клонируйте репозиторий**
   ```bash
   git clone <url>
   cd qa-mesto```
   
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Для macOS/Linux
   .venv\Scripts\activate     # Для Windows
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Установите браузеры Playwright
    ```bash
   playwright install
   ```
5. Настройте переменные окружения:
   - Скопируйте .env.example в .env.dev 
   - Заполните реальные данные (URL, пользователи)
    ```bash
   cp .env.example .env.dev
   ```
6. Запустите тесты:
   ```bash
    pytest                          # все тесты
    pytest tests/test_login.py      # конкретный файл
    pytest --env stage              # выбрать окружение (dev/stage)
    pytest --browser firefox        # выбрать браузер
   ```
### Просмотр отчёта Allure локально

```bash
# Сгенерировать и открыть отчёт
allure generate allure-results --clean
allure open allure-report
```

## 🐳 Запуск в Docker

Проект контейнеризирован. Это гарантирует, что тесты запустятся в изолированной среде с корректными версиями Python и браузеров Playwright без необходимости их локальной установки.

### Основные команды

По умолчанию тесты запускаются на окружении `dev` в браузере `chromium`.  


| Команда | Описание |
| :--- | :--- |
| `docker-compose up` | Собрать (если не собран) и запустить тесты по умолчанию |
| `docker-compose up --build` | Принудительно пересобрать образ и запустить тесты |
| `docker-compose down` | Остановить и удалить созданные контейнеры |

### Гибкий запуск (конкретные тесты/браузеры)

Вы можете передавать любые параметры `pytest` напрямую в контейнер:

*   **Выбор браузера:**
    ```bash
    docker-compose run playwright-tests pytest --browser chromium
    ```
*   **Запуск по маркеру (например, smoke):**
    ```bash
    docker-compose run playwright-tests pytest -m smoke
    ```
*   **Запуск конкретного файла с тестами:**
    ```bash
    docker-compose run playwright-tests pytest tests/test_login.py
    ```

### Отчеты
После выполнения команд результаты тестов автоматически появятся в папках:
- `./allure-results` — данные для Allure.
- `./playwright-report` — стандартные отчеты (скриншоты, видео).

# CI/CD

Проект использует **GitHub Actions** для автоматического запуска E2E-тестов, формирования Allure‑отчёта и публикации его на **GitHub Pages**.

### Триггеры

- **Push** в ветку `main` – запускает тесты в окружении `dev` с браузером `chromium`.
- **Ручной запуск** (`workflow_dispatch`) – позволяет выбрать:
  - Окружение (`dev` / `stage`)
  - Браузер(ы) (`chromium`, `firefox`, `webkit` или `all`)
  - Маркер тестов (`smoke`, `regression` и т.д.)
  - Конкретные файлы/папки с тестами

### Что делает pipeline

| Джоба | Описание |
|-------|----------|
| `validate_pipeline_inputs` | Проверяет переданные параметры (окружение, браузеры). |
| `setup_matrix` | Формирует матрицу браузеров для параллельного запуска. |
| `testing` | Запускает тесты в Docker Compose для каждого браузера из матрицы. Результаты сохраняются как артефакты `allure-results-*`. |
| `generate_allure_report` | Скачивает все артефакты, объединяет их и генерирует Allure‑отчёт. |
| `publish_to_pages` | Публикует сгенерированный отчёт на GitHub Pages. |

### Как запустить тесты вручную

1. Перейдите на вкладку **Actions** → **UI Tests Pipeline**.
2. Нажмите **Run workflow**.
3. Задайте параметры:
   - **TARGET_ENV** – окружение (`dev` или `stage`)
   - **BROWSER_LIST** – браузер(ы): `chromium`, `firefox`, `webkit`, `all`
   - **TEST_TYPE** – pytest маркер (например, `smoke`)
   - **TEST_FILES** – путь к тестам (по умолчанию `tests/`)
4. Нажмите **Run workflow**.

### Как посмотреть отчёт

1. После завершения workflow перейдите в **Settings** → **Pages** вашего репозитория.
2. Там будет указана ссылка на опубликованный сайт (например, `https://<username>.github.io/<repo>/`).
3. Отчёт автоматически обновляется при каждом успешном запуске тестов.

### Настройка GitHub Pages (один раз)

Чтобы деплой работал, в настройках репозитория (`Settings` → `Pages`) выберите источник **"GitHub Actions"**. После первого запуска всё настроится автоматически.

### Примечания

- При **push** в `main` тесты всегда запускаются с параметрами: окружение `dev`, браузер `chromium`, все тесты из `tests/`.
- Результаты для каждого браузера сохраняются отдельно, а затем объединяются в общий отчёт.
- Код тестов и конфигурация не содержат секретов – все чувствительные данные (URL, логины, пароли) хранятся в **GitHub Secrets** (`DEV_URL`, `DEV_USERS`, `STAGE_URL`, `STAGE_USERS` и т.д.).
